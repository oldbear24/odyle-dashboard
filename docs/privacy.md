# Privacy and persistence

Discord authenticates the application account. PocketBase stores the provider identity mapping and account email/display name needed for sign-in, plus memberships and each character's region/server, name, Odyle total and observation timestamps. The room API exposes display names and opted-in character data, not account emails, authentication secrets or Discord tokens.

Characters belong to accounts. Leaving, closing a room or signing out does not erase stored values. Each change of a character's Odyle is also kept for 30 days as its history, visible to the owner and to rooms the character is shared in, and deleted after that.

Your data, your choice: **Account & data** downloads everything stored for your account as one JSON file (account, sign-in identity, characters and their history, rooms, wishlist entries, planned runs, tasks, Windows app sessions and paired Windows apps), and deletes single characters or the whole account. Deleting the account removes its characters, history, memberships, wishlist entries and tasks; rooms it owned pass to their longest-standing player, or close. The server records when the account last used Odyle (at most hourly). Operators may set a period after which unused accounts are deleted automatically; by default accounts are kept until their owner deletes them. **Sign out everywhere** ends every other browser sign-in and every paired Windows app. Sharing is chosen per character and room; turning it off immediately hides that character from other room members while keeping it in the owner's account. Last saved values may be stale or offline; they remain visible with their timestamp where sharing is enabled, but are excluded from fresh readiness.

The app may detect the own character's name, server and region from game packets and save those normalized identity fields to the paired account. Manual identity setup uses the same limited endpoint. This creates an unknown reading, not a confirmed zero; it cannot set Odyle, ownership, observation timestamps or reading confidence. Repeating a saved identity preserves its existing history.

Character pictures: the backend sends each saved character's name, server and region to PLAYNC's public AION 2 character search and downloads the official portrait it lists, about once a day per character. Browsers load pictures only from the Odyle backend, never from NCSOFT. Players cannot upload or change pictures. Picture files are served from unguessable links without sign-in, like most chat avatars; the backend hands those links only to the owner and to rooms the character is shared in, but anyone who is given a link can open it.

Windows app downloads and updates: the backend asks GitHub's public API for the newest release of the Windows app at most every ten minutes and passes the version and package links to browsers; no account data is involved and browsers do not contact GitHub until a download link is clicked. An installed Windows app contacts GitHub itself (`api.github.com`, `github.com`) about every six hours to look for and download new releases, sending only a standard request that names its version.

Manual totals are rejected. The Windows reader follows the local AION2 process TCP connections using the OS connection table and reads packets through Npcap. It does not read game memory or modify packets/gameplay. Raw traffic remains in local bounded memory and is neither written to disk nor sent to PocketBase. Decoded totals are published under the adapter name `global-reference-v1`; the backend stores readings only from adapters it lists. Historical manual values remain stored but invalid for current readiness. Confirmed zero is a real value; unknown is displayed as a dash. A heartbeat updates presence without reconfirming energy. Session rotation and character switching invalidate current confidence without erasing last saved totals.

The dashboard keeps its sign-in token in the browser's localStorage (`odyle.account`), together with the last opened page (`odyle.location`), the chosen language (`odyle.language`) and, on the room owner's browser, the invite codes it created until they expire (`odyle.invites`; the server keeps only their digests). Invite links carry the code in the URL fragment, which browsers do not send to servers. Every tab of that browser shares the sign-in and it survives closing the browser; it ends when you choose **Sign out of this browser**, which clears the sign-in and the last page, when you **Sign out everywhere** from another browser, or after seven days without opening the dashboard. On a shared computer, sign out when you are done. Windows credentials are protected by DPAPI for the current OS user. The five-minute one-use desktop code pairs the app to its owner's account; do not share it with another person. A paired app keeps a device key that lets it sign in again without a new link; the server stores only its digest with the pairing and last sign-in times, and deletes it when the app disconnects, the account signs out everywhere or is deleted (an account keeps its 10 most recently used pairings). Room invitations are separate and never grant another account ownership of your characters.

Operators: the PocketBase dashboard's Odyle page shows superusers which accounts have a Windows app connected and the requests those apps send (account name, character identity and value, session ids, timings and rejection reasons; never tokens, codes or game traffic). The newest 200 requests are kept in server memory only, are not written to the database and disappear on restart. The same data is already stored or derivable in the database superusers administer.

Request/IP logs and analytics are disabled by default. Back up the PocketBase database to retain user data. Provider client secrets stay on the backend; never include them in browser environment variables or source control.
